# Local test data and verification

The backend's regular TEST_MODE store is `backend/data/test-data.json`. Starting
the backend does not create a user or seed records. Register a local user through
the application or use the separate demo store below.

## Demo seed and reset

From `backend/`, run:

```sh
npm run seed:test
npm run reset:test
```

Both commands require `TEST_MODE=true` and refuse to run in `NODE_ENV=production`.
They operate only on `backend/data/demo-test-data.json`, a dedicated ignored file;
they do not modify the regular test store or connect to MongoDB. Seeding preserves
an existing demo dataset and reports its counts when run again. To intentionally
rebuild after changing test data, run reset first, then seed. The harmless sample
PDF is stored under `backend/uploads/documents` and is removed by reset.

Demo login:

```text
Email: demo@example.com
Password: Demo@12345
```

These credentials are test-only and must not be used outside local TEST_MODE.

The dataset creates five lifecycle states (draft, upcoming, ongoing, completed,
archived), five PIs covering unpaid, partial, paid, and overpaid balances, two
Tax Invoices via the conversion controller, split and full payments, three
payouts, five work items, a sample event PDF, and activities generated by those
operations. The seed invokes application controllers directly; it does not
require an HTTP listener.

To reconcile legacy financial records in the regular TEST_MODE store, run:

```sh
npm run repair:test-finance
```

This uses the shared financial service and recorded payment ledger. It refuses
to run unless `TEST_MODE=true` outside production.

## Checks

```sh
npm test
npm run check:data-integrity
npm run check:event-integrity
npm run check:invoice-integrity
cd ../frontend && npm run lint
npm run build
```

The frontend production build can run without a backend URL and then uses
same-origin `/api` requests. Set `VITE_BACKEND_URL` to the real HTTPS backend
origin when deploying the frontend separately from its API.

For local application testing, set backend `TEST_MODE=true`, frontend
`VITE_BACKEND_URL=http://localhost:3000`, and run the backend and frontend
development servers. To run the backend against the demo store, first seed it,
then run `cd backend && npm run start:test-demo`. Production mode requires
`TEST_MODE=false`, a MongoDB URI,
a production JWT secret, and deployed HTTPS origins as documented in
`PRODUCTION.md`. No production or Vercel environment is modified by these
commands.
